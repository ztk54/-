# 堆
>本篇博客将带你了解一种特殊的二叉树——堆
## 堆基本概念
堆是一种特殊的二叉树结构，本质为基于**完全二叉树**的顺序存储数组，堆通常是一个可以被看做一棵树的数组对象，所以我们可以通俗理解堆相较于普通的二叉树对于空间节点的利用率更高，因此我们使用**数组**来作为堆的底层数据结构。
## 堆的基本代码实现
### 堆的定义
```c
typedef int HeapDataType;
typedef struct
{
	int* arr;
	int size;
	int capacity;
}HP;
```
其中size表示目前堆中的元素个数，capacity表示堆的最大元素个数。
### 堆的销毁和初始化
```c
void HeapInit(HP* php)
{
	php->arr = NULL;
	php->capacity = php->size = 0;
}

void HeapDestroy(HP* php)
{
	if (php->arr)
		free(php->arr);
	php->arr = NULL;
	php->capacity = php->size = 0;
}
```
### 大堆和小堆
在我们实现堆元素的插入之前，让我们先来了解一下，**大堆和小堆**， 大堆每一个子树都满足双亲大于两个孩子；小堆，每个子树都满足双亲小于孩子。因此我们可以很容易的得出来，大堆的堆顶就是堆的**最大元素**，小堆的堆顶就是堆的**最小元素**。这对于我们后续实现堆排序大有裨益。
### 向上调整算法
经过我们上面学习过的大堆和小堆，我们可以知道，建堆**并不是**简简单单的插入一个元素，而是要符合特定的数据结构特征。因此就有了我们的**向上调整算法**，即每插入一个元素，我们就需要自下向上调整堆，使其符合大堆/小堆的特性。
```c
void Adjustup(HeapDataType* arr, int child)
{
	int parent = (child - 1) / 2;
	while (child > 0)
	{
		//大堆>  小堆<
		if (arr[child] > arr[parent])
		{
			swap(&arr[child], &arr[parent]);
			child = parent;
			parent = (child - 1) / 2;
		}
		else
		{
			break;
		}
	}
}
```
我们理解上述代码也需要了解堆中孩子和父亲对应的下标的关系，即父亲节点`parent=(child-1)/2`，左孩子节点`leftchild=parent*2+1`，然后从最底部不断向上迭代，就实现了我们的建堆思想。
### 插入元素
学会了如何建堆，那插入元素只分为了检查是否需要扩容，插入元素，向上调整这几步。
```c
void HeapPush(HP* php, HeapDataType x)
{
	assert(php);
	if (php->capacity == php->size)
	{
		int newCapacity = php->capacity == 0 ? 4 : 2 * php->capacity;
		HeapDataType* tem = (HeapDataType*)realloc(php->arr, newCapacity * sizeof(HeapDataType));
		if (tem == NULL)
		{
			perror("Realloc Failed");
			exit(1);
		}
		php->arr = tem;
		php->capacity = newCapacity;
	}
	php->arr[php->size] = x;
	Adjustup(php->arr, php->size);
	php->size++;
}
```
### 向下调整算法
```c
void Adjustdown(HeapDataType* arr, int parent, int n)
{
	int child = parent * 2 + 1;
	while (child < n)
	{
		//大堆<  小堆>
		if (child + 1 < n && arr[child] < arr[child + 1])
		{
			child++;
		}
		//大堆>  小堆<
		if (arr[child] > arr[parent])
		{
			swap(&arr[child], &arr[parent]);
			parent = child;
			child = parent * 2 + 1;
		}
		else
		{
			break;
		}
	}
}
```
向下调整算法与向上调整算法基本类似，只不过是从上向下迭代，并且是根据父节点找到孩子节点。
### 删除元素
我们删除堆中的元素，是通过**交换**堆顶和堆底元素，并且使得**size--**，然后再次向下调整建堆即可。
```c
void swap(int* x, int* y)
{
	int tem = *x;
	*x = *y;
	*y = tem;
}

bool HeapEmpty(HP* php)
{
	assert(php);
	return php->size == 0;
}

void HeapPop(HP* php)
{
	assert(!HeapEmpty(php));
	swap(&php->arr[0], &php->arr[php->size - 1]);
	php->size--;
	Adjustdown(php->arr, 0, php->size);
}
```
## 堆排序
从我们之前已知的大堆和小堆的描述中我们可以得知一个非常关键的点，即大堆的**堆顶是最大的元素**，小堆的堆顶是最小的元素。假如我们先对于一系列连续的元素建立大堆，然后不断**交换堆顶和堆底**，再次自下向上调整堆，循环这个过程，那么我们不就是实现了排序吗？
```c
void HeapSort(int* arr, int n)
{
	//Adjustdown实现堆
	for (int i = (n - 1 - 1) / 2;i >= 0;i--)
	{
		Adjustdown(arr, i, n);
	}
	////Adjustup实现堆
	//for (int i = 0;i < 0;i++)
	//{
	//	Adjustup(arr, i);
	//}
	int end = n - 1;
	while (end)
	{
		swap(&arr[0], &arr[end]);
		Adjustdown(arr, 0, end);
		end--;
	}
}
```
### 为何选择向下调整建堆
>从建堆的时间复杂度来看，向下调整算法要远优于向上调整算法，下面我们以满二叉树为例来分析一下两者差距。

#### 向上调整建堆的时间复杂度
向上调整建堆的核心是：每插入一个元素，从底部向上调整。对于深度为 $h$ 的满二叉树：
- 第 $1$ 层（根节点）：$2^0$ 个节点，每个最多向上调整 $0$ 次
- 第 $2$ 层：$2^1$ 个节点，每个最多向上调整 $1$ 次
- 第 $3$ 层：$2^2$ 个节点，每个最多向上调整 $2$ 次
- ...
- 第 $h$ 层（叶子节点）：$2^{h-1}$ 个节点，每个最多向上调整 $h-1$ 次

因此向上调整建堆的总移动步数为：

$$T_{up} = 0 \times 2^0 + 1 \times 2^1 + 2 \times 2^2 + ... + (h-1) \times 2^{h-1}$$

利用错位相减法可得：

$$T_{up} = (h-2) \times 2^h + 2$$

又因为 $n = 2^h - 1$，即 $h = \log_2(n+1)$，代入得：

$$T_{up} \approx n\log_2 n$$

即向上调整建堆的时间复杂度为 **O(n log n)**。

#### 向下调整建堆的时间复杂度
向下调整建堆是从最后一个非叶子节点开始，自下而上依次向下调整。对于同样的满二叉树：
- 第 $h$ 层（叶子）：$2^{h-1}$ 个节点，不需要向下调整
- 第 $h-1$ 层：$2^{h-2}$ 个节点，每个最多向下调整 $1$ 次
- 第 $h-2$ 层：$2^{h-3}$ 个节点，每个最多向下调整 $2$ 次
- ...
- 第 $1$ 层（根）：$2^0$ 个节点，最多向下调整 $h-1$ 次

总移动步数为：

$$T_{down} = 0 \times 2^{h-1} + 1 \times 2^{h-2} + 2 \times 2^{h-3} + ... + (h-1) \times 2^0$$

即：

$$T_{down} = \sum_{k=0}^{h-1} k \cdot 2^{h-1-k}$$

同样错位相减可得：

$$T_{down} = 2^{h+1} - h - 2$$

代入 $n = 2^h - 1$，$h = \log_2(n+1)$：

$$T_{down} \approx 2n - \log_2 n - 2$$

即向下调整建堆的时间复杂度为 **O(n)**。

#### 直观理解
>为什么会有这么大的差距？核心原因在于：完全二叉树中**节点数量随深度指数增长**——越靠近底层，节点越多。向上调整对底层节点（数量最多）的调整次数最多；而向下调整对顶层节点（数量最少）的调整次数最多。因此向下调整建堆的效率远高于向上调整建堆，这也是堆排序建堆时优先选用向下调整的原因。

## Top-K 问题
>堆的另一个经典应用是 Top-K 问题：从海量数据中找出最大（或最小）的 K 个元素。常规做法是排序后取前 K 个，时间复杂度为 O(n log n)；而用堆可以将复杂度降到 O(n log k)，当 k 远小于 n 时优势明显。

### 思路
以求最大的 K 个元素为例：
1. 用前 K 个元素建一个**小堆**（堆顶是最小元素，作为"门槛"）
2. 遍历剩余元素，若当前元素**大于堆顶**，说明堆顶不够大，替换堆顶并向下调整
3. 遍历结束后，堆中剩下的就是最大的 K 个元素

>为什么不用大堆？大堆堆顶是最大值，新元素比堆顶大才能入堆——但我们本来就是要找较大的元素，新元素很难比堆顶更大，起不到筛选作用。用小堆，堆顶是"当前 K 个中最小的"，比它大就替换，最终筛出最大的 K 个。

### 代码实现
由于我们需要的是小堆，而前面 `Adjustdown` 实现的是大堆，这里单独写一个小堆版向下调整 `AdjustdownMin`：

```c
// 小堆向下调整
void AdjustdownMin(int* arr, int parent, int n)
{
	int child = parent * 2 + 1;
	while (child < n)
	{
		// 选较小的孩子
		if (child + 1 < n && arr[child] > arr[child + 1])
			child++;
		if (arr[child] < arr[parent])
		{
			swap(&arr[child], &arr[parent]);
			parent = child;
			child = parent * 2 + 1;
		}
		else
			break;
	}
}

void CreatData()
{
	int n = 100000;
	srand((unsigned int)time(0));
	const char* file = "data.txt";
	FILE* fin = fopen(file, "w");
	if (fin == NULL)
	{
		perror("fopen failed");
		return;
	}
	for (int i = 0; i < n; i++)
	{
		int x = (rand() + i) % n;
		fprintf(fin, "%d\n", x);
	}
	fclose(fin);
}

int main()
{
	CreatData();
	FILE* fout = fopen("data.txt", "r");
	if (fout == NULL)
	{
		perror("fopen failed");
		return 1;
	}
	int k = 0;
	printf("请输入k：");
	scanf("%d", &k);
	int* minheap = (int*)malloc(k * sizeof(int));
	if (minheap == NULL)
	{
		perror("malloc failed");
		return 1;
	}
	// 读入前 k 个数据
	for (int i = 0; i < k; i++)
	{
		fscanf(fout, "%d", &minheap[i]);
	}
	// 向下调整建小堆
	for (int i = (k - 1 - 1) / 2; i >= 0; i--)
	{
		AdjustdownMin(minheap, i, k);
	}
	// 遍历剩余 n-k 个数据
	int x = 0;
	while (fscanf(fout, "%d", &x) != EOF)
	{
		if (x > minheap[0])
		{
			minheap[0] = x;
			AdjustdownMin(minheap, 0, k);
		}
	}
	fclose(fout);
	// 输出结果
	for (int i = 0; i < k; i++)
	{
		printf("%d ", minheap[i]);
	}
	free(minheap);
	return 0;
}
```

## 总结
>堆作为一种基于完全二叉树的顺序存储结构，用数组巧妙地实现了高效的优先级管理。建堆时优先选用向下调整（O(n) 而非 O(n log n)），堆排序只需反复交换堆顶堆底再向下调整即可完成原地排序。而 Top-K 问题则展示了堆在"海量数据中筛选极值"场景下的独特优势——用大小为 K 的小堆，以 O(n log k) 的复杂度轻松应对。
>掌握了堆，你就拥有了一个比排序更轻量的"极值筛选器"。
