## 二叉树
> 二叉树是一种重要的数据结构，其在数据的存储，排序等方面多有应用，本篇博客不讲复杂的原理和公式，让我们一起来感受二叉树中递归的暴力美学

# 二叉树的分类
二叉树整体上分为完全二叉树，满二叉树，还有普通二叉树这几大类，其中满二叉树和完全二叉树常使用顺序结构存储（堆便是基于完全二叉树实现的），本篇文章主要探讨的是普通二叉树。
## 二叉树的定义
二叉树，在我看来像是在一条路前的两条岔路口，这两条岔路口又分别指向新的岔路口，我们使用左右孩子的说法来表示不同的分支，因此二叉树的定义如下：
```c
typedef struct BinaryTreeNode
{
	BTDataType data;
	struct BinaryTreeNode* left;
	struct BinaryTreeNode* right;
}BTNode;
```
## 二叉树的基础算法实现
### 前序遍历
前序遍历我们可以简单的理解为，按照**根左右**的顺序进行遍历，即为先打印出根节点，然后递归到左子树，打印完左子树的根节点，再递归到右子树。不过既然是递归，那么必然有终止条件，即递归到了二叉树的**最底部**则销毁函数栈帧，返回后向上回溯，具体代码实现如下：
```c
void BinaryTreePrevOrder(BTNode* root)
{
	if (root == NULL)
	{
		printf("NULL ");
		return;
	}
	printf("%c ", root->data);
	BinaryTreePrevOrder(root->left);
	BinaryTreePrevOrder(root->right);
}
```
> **复杂度**：时间复杂度 O(n)，每个节点恰好访问一次；空间复杂度 O(h)，h 为树高，来自递归调用栈的深度。

### 中序遍历
中序遍历与前序遍历相似，可以简记为**左根右**的顺序来遍历。如果我们前期暂时无法完全明白递归回溯的过程，那么我们可以把**printf**语句看作根，其余两条看作左和右，按照这样的顺序便可以巧记前中后三种遍历。代码实现如下：
```c
void BinaryTreeInOrder(BTNode* root)
{
	if (root == NULL)
	{
		printf("NULL ");
		return;
	}
	BinaryTreeInOrder(root->left);
	printf("%c ", root->data);
	BinaryTreeInOrder(root->right);
}
```
> **复杂度**：时间复杂度 O(n)，空间复杂度 O(h)。

### 后序遍历
与前序、中序遍历相似，我们依旧可以按照上面的技巧得出后序遍历的代码。前序和后序在递归结构上高度对称，区别仅在于根节点的访问时机不同——前序优先处理根，后序最后处理根。这一对称性在二叉树 oj 题中经常用到，代码实现如下：
```c
void BinaryTreePostOrder(BTNode* root)
{
	if (root == NULL)
	{
		printf("NULL ");
		return;
	}
	BinaryTreePostOrder(root->left);
	BinaryTreePostOrder(root->right);
	printf("%c ", root->data);
}
```
> **复杂度**：时间复杂度 O(n)，空间复杂度 O(h)。

### 节点个数
求二叉树的节点个数自然离不开**递归**的思想，我们最容易想到的就是`int BinaryTreeSize(BTNode* root)`这样的函数，每当找到一个非空节点，那我们就`size++`，最后返回size的值便可。这样是可行的，但是这里面也埋着几个坑，假如说我们是把size定义在函数内，那在回溯销毁函数栈帧的过程中，size作为一个形参也**同时被释放**，不能**真正影响**到size的值，有人提到了那我可以搞一个全局变量size啊，这样就不会被释放了，这样自然是可以的，但是碍于美观，我推荐大家在主函数里面定义一个size，然后用指针（**为了影响实参**）的形式传递到函数中，代码如下：
```c
int BinaryTreeSize(BTNode* root,int *size)
{
	if (root == NULL)
	{
		return 0;
	}
	(*size)++;
	BinaryTreeSize(root->left,size);
	BinaryTreeSize(root->right,size);
	return *size;
}
int main()
{
	int size=0;
	BinaryTreeSize(root,&size);
}
```
不过比起来上面这种写法，我更推荐一种更加原生态，符合**递归美学**的求法：
```c
int BinaryTreeSize(BTNode* root)
{
	if (root == NULL)
	{
		return 0;
	}
	return 1 + BinaryTreeSize(root->left) + BinaryTreeSize(root->right);
}
```
> **复杂度**：时间复杂度 O(n)，空间复杂度 O(h)。写法二的递推公式为 `f(root) = 1 + f(left) + f(right)`，将原问题分解为子问题之和，是典型的分治思想。

### 叶子节点
叶子节点指这个节点左右孩子只指向两个**NULL**，这里最重要的就是递归结束的条件，一是根节点已经为空了，那么就开始回溯；二是若根节点的左右孩子均为NULL，那么就可以`return 1`了，具体代码实现如下：
```c
int BinaryTreeLeafSize(BTNode* root)
{
	//这里依旧要检查root为空的情况，否则可能会对NULL发生解引用现象
	if (root == NULL)
	{
		return 0;
	}
	if (root->left == NULL && root->right == NULL)
	{
		return 1;
	}
	return BinaryTreeLeafSize(root->left) + BinaryTreeLeafSize(root->right);
}
```
> **复杂度**：时间复杂度 O(n)，空间复杂度 O(h)。

### 第k层节点个数
我们怎么才能知道这已经到达第k层了呢，在**每次递归**的时候我们将k减1，当k=1并且节点不为NULL的时候，我们便是找到了第k层的一个节点，具体代码实现如下：
```c
int BinaryTreeLevelKSize(BTNode* root, int k)
{
	//注意这里两个if判断不能更改顺序，否则NULL也被当为了有效节点
	if (root == NULL)
	{
		return 0;
	}
	if (k == 1)
	{
		return 1;
	}
	return BinaryTreeLevelKSize(root->left, k - 1)
		+ BinaryTreeLevelKSize(root->right, k - 1);
}
```
> **复杂度**：最坏情况 O(n)（k 很大时需要遍历整棵树），空间复杂度 O(h)。

### 深度
在我看来求深度的核心思想可以看作一个数学模型，（ps：递归算法倘若能抽象出来**对应数学模型**将事半功倍），对于二叉树最高层的深度可以看作`1+左右子树较深的一个`，所以我们依旧可以使用递归来解决问题，代码实现如下：
```c
int BinaryTreeDepth(BTNode* root)
{
	if (root == NULL)
	{
		return 0;
	}
	int left = BinaryTreeDepth(root->left);
	int right = BinaryTreeDepth(root->right);
	return 1 + (left > right ? left : right);
}
```
> **复杂度**：时间复杂度 O(n)，空间复杂度 O(h)。这里先把左右深度分别存到 `left` 和 `right` 再比较，是经典的**后序遍历**思路——先拿到子问题的结果再做决策。递推公式为 `depth(root) = 1 + max(depth(left), depth(right))`。

### 查找元素x
如果粗暴地左右同时递归查找元素 x，相当于把整棵树遍历一遍，即使目标在左子树第一个节点就找到了，右子树依然会被白白搜完，造成不必要的性能浪费。

因此我们需要引入**剪枝**的思想：先在左子树中查找，如果找到了，立刻返回结果，不再去右子树做无用功；只有左子树没找到时，才进入右子树继续搜索。代码如下：
```c
BTNode* BinaryTreeFind(BTNode* root, BTDataType x)
{
	if (root == NULL)
	{
		return NULL;
	}
	if (root->data == x)
	{
		return root;
	}
	BTNode* left = BinaryTreeFind(root->left, x);
	if (left)
	{
		return left;  // 左子树找到了，直接返回，剪掉右子树的搜索
	}
	BTNode* right = BinaryTreeFind(root->right, x);
	if (right)
	{
		return right;
	}
	return NULL;
}
```
> **复杂度**：最坏情况 O(n)（元素不存在或在最右下角），最好情况 O(1)（根节点就是目标）。得益于剪枝，平均情况下优于全树遍历。

## 算法总结

| 算法       | 核心思想              | 关键技巧        | 时间复杂度 |
| -------- | ----------------- | ----------- | ----- |
| 前序遍历     | 根 → 左 → 右         | 递归序         | O(n)  |
| 中序遍历     | 左 → 根 → 右         | 递归序         | O(n)  |
| 后序遍历     | 左 → 右 → 根         | 递归序，子问题先行   | O(n)  |
| 节点个数     | `1 + 左 + 右`       | 分治          | O(n)  |
| 叶子节点个数   | 左右均为 NULL 则返回 1   | 双重终止条件      | O(n)  |
| 第 k 层节点数 | k 递减至 1           | 层数计数器       | O(n)  |
| 深度       | `1 + max(左深, 右深)` | 后序遍历 + 最值比较 | O(n)  |
| 查找元素 x   | 先左后右，找到即停         | 剪枝 / 短路     | O(n)  |

可以观察到，这些算法都遵循同一个套路：**定义好递归终止条件，再将大问题拆分成对左右子树的子问题**。掌握了这个规律，大部分二叉树递归问题都能迎刃而解。
