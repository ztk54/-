# 三大进阶排序：希尔排序、堆排序、计数排序

> 上一篇我们讲了冒泡、直接插入、直接选择三种基本排序（O(n²)）。本文进入进阶篇：希尔排序是对直接插入排序的改进，通过分组预排序大幅降低时间复杂度；堆排序利用堆这种数据结构，稳定给出 O(n log n)；计数排序则跳出"比较"的框架，用空间换时间突破理论下限。三者各有特色，是理解排序算法多样性的关键一步。

---

## 希尔排序

### 算法思想

**希尔排序**是直接插入排序的升级版。回忆一下直接插入排序的特点：对于**基本有序**的数组，它的效率非常高（接近 O(n)）。希尔排序正是利用这一点——先通过较大的间隔分组，让元素大步跳跃到大致正确的位置；再逐步缩小间隔，让数组越来越有序；最后间隔为 1 时，做一次标准插入排序收尾。

核心操作：按**增量 gap**将数组分成若干子序列，对每个子序列做直接插入排序。

### 具体步骤

1. 设定初始增量 `gap = n`。
2. 每轮 `gap = gap / 3 + 1`，将数组分为 gap 组，每组由相隔 gap 的元素组成。
3. 对每组进行直接插入排序（元素比较和移动的步长是 gap 而非 1）。
4. `gap` 逐渐减小，重复步骤 2-3，直到 `gap = 1` 时做最后一次全量插入排序。

以一个数组 `[9, 1, 5, 7, 3, 8, 2, 6, 4]` 为例，gap 取 4 时：

```
原始数组：[9, 1, 5, 7, 3, 8, 2, 6, 4]
                     ↓ gap=4 分组
第0组：arr[0]=9, arr[4]=3, arr[8]=4  → 排序后：3, 4, 9
第1组：arr[1]=1, arr[5]=8            → 排序后：1, 8
第2组：arr[2]=5, arr[6]=2            → 排序后：2, 5
第3组：arr[3]=7, arr[7]=6            → 排序后：6, 7
                     ↓ 结果
gap=4 后：[3, 1, 2, 6, 4, 8, 5, 7, 9]

gap 缩为 2，继续分组排序...
gap 缩为 1，做最后一次插入排序 → 全部有序
```

可以看到，gap=4 时第 0 组的 9 跨越 4 个位置和 3 交换，再和 4 比较，一次移动就跳过了多个元素，比普通插入排序每次只移动一位快得多。

### 代码实现

```c
void ShellSort(int* arr, int n)
{
    int gap = n;
    while (gap > 1)
    {
        gap = gap / 3 + 1;          // gap 递减，最后一定为 1
        for (int i = 0; i < n - gap; i++)
        {
            int end = i;
            int tmp = arr[end + gap];
            while (end >= 0)
            {
                if (arr[end] > tmp)
                {
                    arr[end + gap] = arr[end];
                    end -= gap;      // 步长为 gap
                }
                else
                {
                    break;
                }
            }
            arr[end + gap] = tmp;
        }
    }
}
```

> **gap 公式**：`gap = gap / 3 + 1` 是 Knuth 提出的经典取法，保证 gap 序列递减且最后为 1。其他常见取法还有 `gap = gap / 2`（效率略低），但无绝对最优，取决于数据。

### 复杂度与稳定性

| 指标 | 说明 |
|------|------|
| **最好时间复杂度** | O(n) — 数组基本有序，gap=1 时一轮完成 |
| **最坏时间复杂度** | O(n²) — 取决于 gap 序列，最坏退化为插入排序 |
| **平均时间复杂度** | O(n^1.3) ~ O(n^1.5) — 显著优于 O(n²) |
| **空间复杂度** | O(1) — 原地排序 |
| **稳定性** | **不稳定** — 相同元素可能被分到不同组，跨越交换 |

## 堆排序

### 算法思想

**堆排序**利用**堆**（Heap）这种数据结构来排序。堆是一个近似完全二叉树，分为**大顶堆**（父节点 ≥ 子节点）和**小顶堆**（父节点 ≤ 子节点）。

核心思路分两步：
1. **建堆**：把数组构建成大顶堆，此时堆顶（arr[0]）是最大值。
2. **排序**：反复将堆顶与末尾交换，最大值"沉底"，剩余元素重新调整成堆，直到全部有序。

对于之前在《堆》那篇博客中学过的向下调整（AdjustDown），这里会直接复用。

### 具体步骤

1. **建堆**：从最后一个非叶子节点 `(n - 2) / 2` 开始，自底向上对每个节点做向下调整，构建大顶堆。
2. **排序循环**：
   - 交换 `arr[0]`（当前最大值）和 `arr[end]`（堆的最后一个元素）
   - 对 `[0, end)` 范围做一次向下调整，恢复大顶堆
   - `end--`，缩小区间，重复直到 `end = 0`

以数组 `[4, 6, 8, 5, 9]` 为例：

```
建堆过程（自底向上调整）：
原始：[4, 6, 8, 5, 9]
调整后（大顶堆）：[9, 6, 8, 5, 4]   ← 9 在堆顶

排序过程：
第1次：交换 9↔4 → [4, 6, 8, 5, |9]，调整 → [8, 6, 4, 5, |9]
第2次：交换 8↔5 → [5, 6, 4, |8, 9]，调整 → [6, 5, 4, |8, 9]
第3次：交换 6↔4 → [4, 5, |6, 8, 9]，调整 → [5, 4, |6, 8, 9]
第4次：交换 5↔4 → [4, |5, 6, 8, 9]，完成
```

### 代码实现

```c
void swap(int* a, int* b)
{
    int tmp = *a;
    *a = *b;
    *b = tmp;
}

// 向下调整：将以 parent 为根的子树调整为大顶堆
void Adjustdown(int* arr, int parent, int n)
{
    int child = parent * 2 + 1;
    while (child < n)
    {
        // 选出左右孩子中较大的那个
        if (child + 1 < n && arr[child] < arr[child + 1])
        {
            child++;
        }
        // 孩子比父亲大，交换并继续
        if (arr[child] > arr[parent])
        {
            swap(&arr[child], &arr[parent]);
            parent = child;
            child = parent * 2 + 1;
        }
        else
        {
            break;
        }
    }
}

void HeapSort(int* arr, int n)
{
    // 1. 建堆：从最后一个非叶子节点开始，自底向上
    for (int i = (n - 1 - 1) / 2; i >= 0; i--)
    {
        Adjustdown(arr, i, n);
    }

    // 2. 排序：逐个将堆顶（最大值）交换到末尾
    int end = n - 1;
    while (end)
    {
        swap(&arr[0], &arr[end]);
        Adjustdown(arr, 0, end);
        end--;
    }
}
```

> **为什么从 `(n - 2) / 2` 开始建堆**：在完全二叉树中，下标 ≥ n/2 的节点都是叶子节点，本身已经是合法的堆。`(n - 2) / 2` 是第一个非叶子节点的下标（即最后一个节点的父节点），从这里往上调整即可完整建堆，时间复杂度 O(n)。

### 复杂度与稳定性

| 指标 | 说明 |
|------|------|
| **最好时间复杂度** | O(n log n) |
| **最坏时间复杂度** | O(n log n) |
| **平均时间复杂度** | O(n log n) |
| **空间复杂度** | O(1) — 原地排序 |
| **稳定性** | **不稳定** — 堆的调整过程会打乱相等元素的相对顺序 |

> 堆排序是 O(n log n) 级别中**唯一空间 O(1)** 的排序算法（归并需要 O(n) 辅助数组，快排需要 O(log n) 递归栈）。代价是常数因子较大，实际速度通常不如快排。

## 计数排序

### 算法思想

前面几种排序都属于**比较排序**，理论上最快只能到 O(n log n)。**计数排序**跳出比较框架，不通过比较元素大小来排序，而是**统计每个值出现了几次**，然后按值的大小顺序还原。

核心思路：用一个额外的计数数组，下标代表元素值，值代表出现次数。这就是典型的"**空间换时间**"。

适合场景：数据范围（max - min）不大，且为整数。比如考试成绩、年龄等。

### 具体步骤

1. 找到数组的最大值 max 和最小值 min，算出范围 `range = max - min + 1`。
2. 创建大小为 range 的计数数组 count，全部初始化为 0。
3. 遍历原数组，`count[arr[i] - min]++` 统计每个元素出现次数。
4. 遍历计数数组，将下标 i 对应的值 `i + min` 按 count[i] 次写回原数组。

拿一次考试分数来说：`[85, 92, 85, 78, 92, 100, 85]`

```
第1步：max = 100, min = 78, range = 100 - 78 + 1 = 23
第2步：创建 count[23]，初始全 0

第3步：遍历统计，arr[i] - min 作为下标
    85 → count[85 - 78] = count[7]++
    92 → count[14]++
    85 → count[7]++     → count[7] = 2
    78 → count[0]++     → count[0] = 1
    92 → count[14]++    → count[14] = 2
    100→ count[22]++    → count[22] = 1
    85 → count[7]++     → count[7] = 3

count 数组（只展示非零位）：
  下标 0 → 分数78 → 1次
  下标 7 → 分数85 → 3次
  下标14 → 分数92 → 2次
  下标22 → 分数100→ 1次

第4步：按顺序还原
  78×1, 85×3, 92×2, 100×1
  → [78, 85, 85, 85, 92, 92, 100]
```

关键技巧：用 `arr[i] - min` 把元素值"映射"到 count 数组下标，这样就算原始数据不从 0 开始（比如 78~100），也能紧凑利用数组空间。

### 代码实现

```c
void CountSort(int* arr, int n)
{
    // 找到最大最小值
    int max = arr[0], min = arr[0];
    for (int i = 0; i < n; i++)
    {
        if (max < arr[i])
            max = arr[i];
        if (min > arr[i])
            min = arr[i];
    }

    // 创建计数数组
    int range = max - min + 1;
    int* count = (int*)calloc(range, sizeof(int));
    if (count == NULL)
    {
        perror("Calloc Fail");
        exit(1);
    }

    // 统计每个元素出现次数
    for (int i = 0; i < n; i++)
    {
        count[arr[i] - min]++;
    }

    // 还原到原数组
    int index = 0;
    for (int i = 0; i < range; i++)
    {
        while (count[i]--)
        {
            arr[index++] = i + min;
        }
    }

    free(count);
}
```

> **max/min 初始化的坑**：不要初始化为 0。如果数组全是负数，max 会一直是 0；如果数组全是正数，min 会一直是 0。正确做法是初始化为 `arr[0]`。

### 复杂度与稳定性

| 指标 | 说明 |
|------|------|
| **时间复杂度** | O(n + range) — n 次统计 + range 次还原 |
| **空间复杂度** | O(range) — 额外计数数组 |
| **稳定性** | **稳定** — 按值顺序还原，等值元素的相对顺序得以保持 |

> **计数排序的局限**：当 range 远大于 n 时（比如只有 `[1, 1000000]` 两个数），会浪费巨大空间。另外它要求数据为整数（或可映射为整数），无法直接对浮点数排序。但它突破 O(n log n) 下限的思路，启发了基数排序、桶排序等更灵活的非比较排序。

## 三种排序对比

|             | 希尔排序       | 堆排序        | 计数排序       |
| ----------- | :---------: | :---------: | :---------: |
| **核心思想**   | 分组插入，逐步逼近 | 堆结构，堆顶取最值 | 统计频次，按值还原 |
| **排序类型**   | 比较排序       | 比较排序       | **非比较排序**   |
| **时间复杂度**  | O(n^1.3)~O(n²) | O(n log n) | O(n + range) |
| **空间复杂度**  | O(1)        | O(1)        | O(range)    |
| **稳定性**    | 不稳定         | 不稳定        | 稳定          |
| **适用场景**   | 中等规模，追求简单  | 要求 O(n log n) 且原地，不在乎稳定性 | 小范围整数，要求线性时间 |

---

## 总结

- **希尔排序**：在直接插入排序基础上引入"分组预排"，时间复杂度降到亚二次级别，实现简单，是不追求绝对 O(n log n) 时的实用选择。
- **堆排序**：O(n log n) 中唯一原地排序，但常数大、不稳定。建堆 O(n) + n 次调整 O(log n) 的组合是经典套路，堆结构的向下调整操作也是面试高频考点。
- **计数排序**：打破比较排序的理论下限，用空间换时间。理解它对后续学习基数排序和桶排序至关重要。

三种算法代表了三种不同的优化方向——**预处理数据**（希尔）、**数据结构辅助**（堆）、**换赛道**（计数），共同展示了排序算法设计的丰富维度。
